# Consistency review — cross-spec conflicts

**Reviewer role:** adversarial consistency critic. Scope: `BRIEF.md`, `00-foundation.md`, `01`–`09`.
Also cross-checked against `_toolchain-findings.md`, which declares itself authoritative on versions.

**Verdict: the spec set is not safe to build from in parallel.** 78 conflicts below. Thirty-three are
**BLOCKERS** — two agents implementing two files as written produce code that does not compile
together, does not run, or silently corrupts data. The specs are individually excellent and mutually
incompatible; almost every conflict is a *name*, a *number*, or a *status code* that two authors each
invented because `00-foundation.md` did not pin it.

**Highest-leverage fix:** `00-foundation.md` currently pins the data model and the route *paths* but
not the module layout, the error-code registry, the constant names, the capability keys, the session
API, or the version pins. Five short additions to `00-foundation.md` (§5a module map, §7a error-code
registry, §7b shared constants, §2a version pins, §6a capability keys) collapse roughly 45 of the 78
rows below. Do that before any implementation agent starts.

Severity: **BLOCKER** = build/runtime breaks or data corrupts · **MAJOR** = wrong behaviour or a
failing acceptance criterion · **MINOR** = drift a reviewer would notice.
